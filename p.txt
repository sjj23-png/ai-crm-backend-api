user.service.tsimport bcrypt from "bcrypt";
import { CreateUserDto } from "../dto/create-user.dto";
import { UserRepository } from "../repositories/user.repository";

export class UserService {

  private repository =
    new UserRepository();

  async create(data: CreateUserDto) {

    const exists =
      await this.repository.findByEmail(data.email);

    if (exists) {
      throw new Error("Email already exists.");
    }

    const passwordHash =
      await bcrypt.hash(
        data.password,
        Number(process.env.BCRYPT_SALT)
      );

    const user =
      await this.repository.create({

        name: data.name,

        email: data.email,

        passwordHash,

        tenantId: data.tenantId,

        roleId: data.roleId

      });

    return user;

  }

  async getAll(tenantId: string) {

    return this.repository.findAll(tenantId);

  }

  async getById(id: string) {

    const user =
      await this.repository.findById(id);

    if (!user) {
      throw new Error("User not found.");
    }

    return user;

  }

  async delete(id: string) {

    await this.repository.delete(id);

    return {

      message: "User deleted successfully."

    };

  }

}

## 3. The Registration Flow Mismatch (Critical Bug)

During the audit, a major architectural disconnect was found between the frontend registration UI and the backend auth module:

```mermaid
sequenceDiagram
    participant FE as Frontend (Signup.tsx)
    participant BE_Auth as Backend Auth (/api/auth/register)
    participant BE_Tenant as Backend Tenant (/api/tenants/register)

    Note over FE: Sends: name, code, email, website,<br/>ownerName, ownerEmail, password, logo (File)
    FE->>BE_Auth: POST /api/auth/register (multipart/form-data)
    Note over BE_Auth: Fail: No multer middleware,<br/>expects: { name, email, password, tenantId, roleId } (JSON)
    BE_Auth-->>FE: 400 Bad Request / Empty Body Error
```

### Issues Found:
1. **Frontend Call Destination:** 
   The frontend [Signup.tsx](file:///d:/A1codes/Chatgptdevelopment/Projects/AI-CRM/apps/web/webs/src/pages/auth/Signup.tsx) submits a `multipart/form-data` payload containing both organization data (name, code, email, website, logo file) and owner user data (ownerName, ownerEmail, password) to `POST /api/auth/register`.
2. **Backend Route Lacks Multipart Parsing:** 
   The `/api/auth/register` route does not use `multer` or any file-parsing middleware. Hence, sending `multipart/form-data` results in an empty `req.body` and a failed request.
3. **Backend Expected Payload Mismatch:** 
   The backend `/api/auth/register` is designed to register an additional user for an *already existing* tenant. It validates against `RegisterSchema` (which requires `tenantId` and `roleId`) rather than creating a new tenant and its owner.
4. **Backend Tenant Route Incompleteness:** 
   While the `/api/tenants/register` route exists on the backend and includes the logo upload middleware, it is commented out in [index.ts](file:///d:/A1codes/Chatgptdevelopment/Projects/AI-CRM/apps/api/src/routes/index.ts). Even if un-commented:
   * The controller doesn't extract the uploaded logo file information from `req.file`.
   * The service doesn't create the corresponding administrator/owner user record in the `User` table, leaving the newly created tenant without an account to log in.

---

## 5. Recommended Solution Plan

To fix the registration and upload issues, the registration endpoint on the backend should be unified to handle tenant signup. We should:

1. Add `uploadTenantLogo.single("logo")` to `/api/auth/register`.
2. Update the signup service to perform the following sequentially inside a transaction:
   * Create a new `Tenant` database entry (saving the logo file name in the `logo` field).
   * Create a default `OWNER` `Role` for that Tenant.
   * Create the owner `User` linked to the Tenant and the new Role.
   * Create a `UserProfile` entry for that user.
